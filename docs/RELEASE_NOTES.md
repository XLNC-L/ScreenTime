## v1.2.2 — 托盘置顶修复、图标落盘

这一版同样**没有新功能**，修的是两个日常用着难受的问题。两个都做了实机验证。

### 重点修复

**点托盘不会把窗口提到最前**

桌面已经有面板、但被别的窗口盖住时，点托盘图标毫无反应。这个问题的排查过程比较曲折，
根因其实是**两层**：

1. `Window.Activate()` 内部只做一次 `SetForegroundWindow`，被 Windows 前台锁拒绝时
   **只返回 false、不抛异常**，于是静默失败。而从前台窗口切到托盘时，
   前台窗口可能属于**提权进程**（PowerToys / Process Lasso 都以管理员运行），
   非提权进程受 UIPI 限制，连 `AttachThreadInput` 都被拦。
2. 更隐蔽的一层：托盘唤醒原来走「启动第二个实例 → 它发现单实例 → 通过命名管道转发」，
   多创建一整个进程只为传一个字节，而且**会偶发失败**——日志里能看到 `Process.Start`
   返回了 pid，界面侧却完全没收到信号，连续五次点击全部无效。

现在的做法：

- **改 Z 序不依赖任何权限**。`SetWindowPos(HWND_TOP)` 把窗口抬到普通窗口层的最上层，
  再去争取键盘焦点；焦点拿不到也不影响「已经置顶」。
  （用 `HWND_TOP` 而不是 `HWND_TOPMOST`，避免把 `WS_EX_TOPMOST` 永久留在窗口上。）
- **托盘点击直接连命名管道**叫醒正在运行的界面，只有确实没有界面进程时才启动新进程。
- 新建窗口的路径（关掉面板后点托盘）也补了置顶，并且等首帧渲染完再抬，
  避免对还没显示的窗口调 `SetWindowPos`。
- 全过程写 `%APPDATA%\ScreenTime\activate.log`，下次有问题能直接看出卡在哪一步。

实测：被最大化窗口盖住、最小化、连续点击三种情况都能正常弹出并置顶，且不再产生多余进程。

**卸载过的软件在历史里没有图标**

图标一直是运行时从 exe 资源里现取、只缓存在内存，进程一重启就失效；
软件卸载或换目录后，历史排行里就只剩一排空白行。

现在提取成功即落盘到 `%APPDATA%\ScreenTime\icons\<哈希>.png`，读取时先查磁盘再现取。
实测 100 个应用共 2.1 MB（平均约 21 KB/个），可以忽略。

> 注意：这个改动**只对以后出现的图标生效**。已经卸载的软件补不回来——
> 源 exe 不存在，磁盘上也没有历史缓存。

### 安装

从下面的 `ScreenTime-Setup-1.2.2.exe` 安装，或直接下载源码自行构建。

- 装到用户目录（`%LocalAppData%\Programs\ScreenTime`），**不需要管理员权限、不弹 UAC**
- 需要 **.NET 8 Desktop Runtime（x64）**，安装向导会检测并给出下载链接
- 未做代码签名，首次运行 Windows 可能提示「未知发布者」，点「更多信息 → 仍要运行」即可
- 可对照 `SHA256SUMS.txt` 校验下载的文件

> 从旧版升级：安装程序会自动结束正在运行的界面与采集器进程，不需要先手动退出托盘。
> 若你装过 v1.2.0，那个包缺少采集器（发布脚本漏打包），直接用本版覆盖即可。

### 已知限制

- 仅 x64，没有 ARM64 构建。
- 浏览器页面级统计只支持 Chrome / Edge。
- 浏览器的 PWA 窗口与浏览器共用进程，时间只能记在浏览器名下。
- 数据库没有自动清理，明细永久保留（约 57 MB/年）。
- 待办列表只看最近 30 天。
- 托盘图标默认收在通知区域的溢出区里，需要先展开才能看到。
