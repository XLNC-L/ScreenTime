## v1.2.1 — 双进程接缝修复、页面收编、网页搜索

这一版**没有新功能**，主要是把 v1.2.0 拆分双进程时留下的接缝补齐，外加一次页面结构调整。

### 重点修复

**开机自启「点了没反应」**
根因不是计划任务，而是设置页在 UI 线程同步读数据库，一旦撞上采集器的写锁抛出
`SQLITE_BUSY`，内部的 `_loading` 标志就永久卡在 `true`，之后**所有开关**都会被静默拦掉。
现在用 `try/finally` 兜底复位；自启状态也改为直接读任务定义文件判断，
不再依赖 `schtasks` 的输出解析（解析失败会把「开着」显示成「关着」）。

**分类下钻是空转的**
点击今日/历史页的分类环形图或图例，原来只是把历史页整页重载一遍，并没有筛选。
现在分类作为导航参数传进历史页，应用排行会按该分类收窄，卡片右上角有「分类：xxx + 清除筛选」。

**应用排行里有两个 ScreenTime**
一个是界面进程，一个是后台采集器。采集器不该被当成用户使用的应用，已加入噪声名单。

**收件箱徽标扫全库**
原来每次启动都把所有使用明细读进内存做区间并集，46 万行实测 522ms，且在主窗口构造时同步执行。
现在只针对未分类应用查，配合新增的复合索引，同样数据量 **73ms**，并改为后台线程刷新。

**其他**
- 「恢复统计」被自动噪声规则覆盖的问题：用户手动设过的忽略标记不再被改写。
- 噪声规则原本有两套（收件箱 40+ 个进程、数据库只有 9 个），已统一为一份。
- 临时目录过滤从来没生效过（SQL 里多写了一个反斜杠），从 Temp 解压运行的安装器现在能正确忽略。
- 浏览器历史回填从界面进程搬到采集器，关掉窗口也会继续补网页地址。
- 界面与采集器同时启动时的数据库迁移竞态，加了跨进程互斥。

### 界面调整

- **删除「报告」页**：它的指标（总时长 / 日均 / 最活跃时段 / 分类占比 / 用途分布 / 每日柱状图）早已并入历史页。
- **删除「应用」页**：导入已安装应用、单应用使用历史、分类 / 用途 / 忽略 / 合并全部并入历史页右键菜单，
  排行卡片右上角新增「导入应用」按钮。
- **今日页右键菜单精简为 3 项**（打开应用 / 定位文件 / 复制路径），管理类操作统一放历史页。
- **网页页删掉「网站分类」**，只保留时间线；顶部新增搜索，按标题 / 域名 / 网址过滤，输入即生效。
- **「分类待办」改名为「待办」**。

### 流畅度

- 右键改分类、设置开关等写操作全部移到后台线程，界面不再等数据库锁。
- 启动时不再每次抢 `journal_mode` 的排他锁；噪声扫描改为每天一次。
- 历史页与网页页的查询、聚合移出 UI 线程，UI 线程只做绑定。
- 历史页查询加了 200ms 防抖与版本号防竞态，快速切日期不会用旧数据覆盖新数据。

### 安装

> ⚠️ **如果你装过 v1.2.0 的安装包**：那个包只打包了界面进程，缺少 `ScreenTime.Agent.exe`，
> 结果是托盘图标和后台采集都不工作（v1.2.0 的发布脚本漏了采集器）。
> 请直接用 1.2.1 覆盖安装，安装程序会自动结束正在运行的旧进程。

从下面的 `ScreenTime-Setup-1.2.1.exe` 安装，或直接下载源码自行构建。

- 装到用户目录（`%LocalAppData%\Programs\ScreenTime`），**不需要管理员权限、不弹 UAC**
- 需要 **.NET 8 Desktop Runtime（x64）**，安装向导会检测并给出下载链接
- 未做代码签名，首次运行 Windows 可能提示「未知发布者」，点「更多信息 → 仍要运行」即可
- 可对照 `SHA256SUMS.txt` 校验下载的文件

> 从 v1.2.0 升级：安装程序会自动结束正在运行的界面与采集器进程，不需要先手动退出托盘。

### 已知限制

- 仅 x64，没有 ARM64 构建。
- 浏览器页面级统计只支持 Chrome / Edge。
- 浏览器的 PWA 窗口与浏览器共用进程，时间只能记在浏览器名下。
- 数据库没有自动清理，明细永久保留（约 57 MB/年）。
- 待办列表只看最近 30 天。
